# 区域地图与虚拟房间

`CORE_AREA` 将整张网格地图放在一个环境对象中，每个格子存描述、地形和对象索引。它与 `CORE_ROOM`、`CORE_VRM` 的对象模型不同，不能只替换继承宏就通用。

| 模块 | 空间模型 | 定位与查找 |
| --- | --- | --- |
| `CORE_ROOM` | 一个房间对应一个对象 | `environment()`、房间出口和原生物品查找 |
| `CORE_AREA` | 一个对象内有多个格子 | 环境对象加 `area_info` 坐标；区域查找限制在当前格 |
| `CORE_VRM` | 按坐标生成多个房间对象 | `VIRTUAL_D` 路由与虚拟房间路径，见 [虚拟对象](../daemons/virtual_d.md) |

## 初始化与坐标

宿主继承 `CORE_AREA`，设置 `x_axis_size`、`y_axis_size` 后调用 `setup()`。它先尝试恢复存档；首次创建时分配网格并保存，再安排刷新。宽度范围为 38～100，高度为 11～100；未设置或超出范围时分别采用 50、20，同时写回尺寸属性。已有存档优先，不会按新的配置自动改变地图大小。

坐标从 0 开始，访问接口使用 `(x, y)`，内部数据为 `area[y][x]`。AREA 的北方是 `y - 1`；VRM 的北方是 `y + 1`，两者不能直接共享坐标转换。`query_info(x, y)` 返回现有格子的 mapping 引用；修改它会直接影响地图。业务代码优先使用 `set_data()`、`set_area_exit()`、`set_loads()` 等方法，不手写 `objects`、`loaded` 或搜索索引。

## 进入、离开与查找

- `area_move(area, who, x, y)` 同步环境、`area_info` 和格子对象索引；`area_move_side(who, me)` 移到 `me` 所在格。成功返回 `1`，拒绝或对象已销毁返回 `0`，宿主移动异常继续传播。它们是定位接口，方向通行、地形和守卫规则由区域移动命令检查。
- 移动尚未发生时失败，会清理目标索引并恢复原坐标；跨区域移动已完成但随后 `init`、GMCP 或 `look` 抛错时，保留实际目标位置。不能将异常简单理解成“玩家还在原地”，也不承诺回滚宿主回调的所有副作用。
- `move_in()` / `move_out()` 只维护格子索引，不执行驱动移动。单独调用 `move_object()` 或 `who->move(area)` 不能完成区域登记。离开区域时使用框架 MOVE 的 `move()`，由它清理旧索引。
- `present()` 保留普通对象的原生语义；在 AREA 内只查当前格，仍可查角色自身背包。命令对象显式查询 AREA 时以同一区域内的 `this_player()` 为坐标来源。没有可确定的区域坐标时返回 `0`，不会任意查整张地图。完整兼容约定见 [模块契约](../module-contracts.md#模拟函数与原生-efun)。
- `tell_area(area, x, y, text, exclude)` 向指定格发送消息；原生 `tell_room()` 面向整个环境对象，两者用途不同。

## 刷新与存档

`set_loads()` 指定某格应补充的对象；`reset()` 安排分批刷新，不清空现有占用索引。加载物需要框架物品的命名、移动和唯一性接口，宿主销毁对象时也应执行相应离开/清理逻辑。

`save()` 在副本中移除 `objects`、`loaded` 运行时索引后保存；成功返回 `1`，无法保存返回 `0`，异常传播。成功和失败都保留当前地图及外部持有的格子引用。存档保留地形和载入配置，运行中的对象不会因地图存档而持久化，恢复后的载入物通过刷新重新创建。

默认 `query_save_file()` 使用区域对象文件名，可能把存档放到源码旁。正式宿主应覆盖为稳定的 `DATA_DIR` 路径，尤其不要将克隆编号当成可恢复的地图 ID。区域恢复用于初始化，不能视为对有人在线的地图进行安全热替换。

`AREA_PATTERN_D->scan_patterns(dir)` 只扫描该目录的 LPC 源文件，同名优先 `.lpc`；重扫替换该目录的旧索引，保留其他目录。模板加载失败会传播异常并保留此前索引。模板只是批量设置格子数据，不提供地貌生成、剧情或 AI 创作服务。
